# SMTP Relay Server Implementation Plan

## Overview
Set up a lightweight Postfix SMTP relay server on a 2GB RAM / 50GB storage Linode instance to enable website microservices to send emails via authenticated SMTP. The server will relay emails to ProtonMail-configured domains.

## Requirements Summary
- **Purpose**: SMTP relay only (no mailboxes, no incoming mail)
- **Domains**: 2 initially, expandable to more
- **Email Volume**: Low (dozens per day per domain)
- **Security**: IP-based restrictions only (no password authentication needed)
- **IP Restriction**: Only allow relay from trusted microservice IP addresses
- **Destination**: ProtonMail accounts with existing MX/TXT records
- **Resource Constraints**: 2GB RAM, 50GB storage

## Technology Stack
- **MTA**: Postfix (relay-only configuration)
- **OS**: Ubuntu 22.04 LTS (recommended) or Debian 12
- **Security**: IP-based restrictions (firewall + Postfix), TLS/SSL for SMTP connections
- **DNS**: SPF, DKIM, DMARC records

## Architecture
```
┌─────────────────────┐
│ Website Microservice│
│  (Static IP)        │
└──────────┬──────────┘
           │ Port 587 (TLS)
           │ No auth needed
           ▼
┌─────────────────────┐
│  Linode Server      │
│  Postfix Relay      │
│  - IP validation    │
│  - Rate limiting    │
│  - Logging          │
└──────────┬──────────┘
           │ Port 25
           │
           ▼
┌─────────────────────┐
│   ProtonMail        │
│   (Final Delivery)  │
└─────────────────────┘
```

## Implementation Steps

### Phase 1: Server Preparation (30 minutes)

#### 1.1 Initial Server Setup
```bash
# Update system packages
apt update && apt upgrade -y

# Set hostname (important for email reputation)
# Use smtp-relay instead of mail since this is a relay-only server
hostnamectl set-hostname smtp-relay.yourdomain.com

# Update /etc/hosts
echo "YOUR_SERVER_IP smtp-relay.yourdomain.com smtp-relay" >> /etc/hosts

# Install required packages
# During installation, you'll see a configuration screen
apt install -y postfix postfix-pcre ca-certificates
```

**IMPORTANT: Postfix Installation Prompts**

During installation, Postfix will show an interactive configuration screen:

1. **General type of mail configuration:**
   - Select: **"Internet Site"**
   - (Use arrow keys to navigate, Enter to select)

2. **System mail name:**
   - Enter: **yourdomain.com** (your primary domain)
   - This is the domain used for mail generated by the system
   - Example: `example.com` (not `smtp-relay.example.com`)

Don't worry if you select the wrong option - you'll manually configure everything in Phase 2 anyway.

**Hostname Choice Explained:**
- Use `smtp-relay.yourdomain.com` (recommended) - clearly indicates purpose
- Alternative: `relay.yourdomain.com` - shorter but still descriptive
- Avoid: `mail.yourdomain.com` - implies full mail server with mailboxes
- Replace `yourdomain.com` with your primary domain

#### 1.2 Firewall Configuration
```bash
# Install ufw if not present
apt install -y ufw

# Allow SSH (important - don't lock yourself out!)
ufw allow 22/tcp

# Allow SMTP submission from specific microservice IPs only
ufw allow from MICROSERVICE_IP_1 to any port 587 proto tcp
ufw allow from MICROSERVICE_IP_2 to any port 587 proto tcp
# Add more as needed for each microservice

# Optional: Allow port 25 from specific IPs for direct SMTP
ufw allow from MICROSERVICE_IP_1 to any port 25 proto tcp
ufw allow from MICROSERVICE_IP_2 to any port 25 proto tcp

# Deny all other SMTP traffic
ufw deny 587/tcp
ufw deny 25/tcp

# Enable firewall
ufw enable
```

**Note**: Replace `MICROSERVICE_IP_1`, `MICROSERVICE_IP_2`, etc. with your actual microservice static IP addresses.

### Phase 2: Postfix Configuration (45 minutes)

#### 2.1 Main Postfix Configuration
Edit `/etc/postfix/main.cf`:

```conf
# Basic settings
myhostname = smtp-relay.yourdomain.com
mydomain = yourdomain.com
myorigin = $mydomain
inet_interfaces = all
inet_protocols = ipv4

# Relay configuration (NOT a local delivery server)
mydestination = localhost
local_recipient_maps =
relay_domains = domain1.com, domain2.com
relayhost =

# Network and relay restrictions
# Add your microservice IPs to mynetworks for IP-based trust
mynetworks = 127.0.0.0/8, MICROSERVICE_IP_1, MICROSERVICE_IP_2
smtpd_relay_restrictions = 
    permit_mynetworks,
    reject_unauth_destination

# Client restrictions - only allow connections from trusted IPs
smtpd_client_restrictions =
    permit_mynetworks,
    reject

# TLS Configuration (for encrypted connections)
smtpd_tls_cert_file = /etc/ssl/certs/ssl-cert-snakeoil.pem
smtpd_tls_key_file = /etc/ssl/private/ssl-cert-snakeoil.key
smtpd_tls_security_level = may
smtpd_tls_loglevel = 1
smtpd_tls_received_header = yes

smtp_tls_security_level = may
smtp_tls_loglevel = 1

# Performance tuning for low volume
default_process_limit = 50
smtpd_client_connection_count_limit = 10
smtpd_client_connection_rate_limit = 30

# Message size limit (10MB default, adjust as needed)
message_size_limit = 10485760

# Logging
maillog_file = /var/log/postfix.log

# Sender restrictions (prevent spoofing)
smtpd_sender_restrictions =
    permit_mynetworks,
    permit_sasl_authenticated,
    reject_unknown_sender_domain,
    reject_sender_login_mismatch
```

#### 2.2 Configure Master Process (Optional - for port 587)
Edit `/etc/postfix/master.cf`:

**Note:** Port 587 configuration is optional. If you're only using IP-based restrictions, the default SMTP port 25 configuration is sufficient. However, port 587 is often preferred for application-to-server connections.

```conf
# Submission port (587) for relay (optional, can use port 25 instead)
submission inet n       -       y       -       -       smtpd
  -o syslog_name=postfix/submission
  -o smtpd_tls_security_level=may
  -o smtpd_client_restrictions=permit_mynetworks,reject
  -o smtpd_relay_restrictions=permit_mynetworks,reject_unauth_destination
```

```bash
# Set up auto-renewal

systemctl start certbot.timer
```

#### 3.2 Post-renewal Hook
Create `/etc/letsencrypt/renewal-hooks/post/postfix-reload.sh`:
```bash
#!/bin/bash
systemctl reload postfix
```

```bash
chmod +x /etc/letsencrypt/renewal-hooks/post/postfix-reload.sh
```

### Phase 4: DNS Configuration (15 minutes)

Configure the following DNS records for each domain:

#### 4.1 A Record
```
smtp-relay.yourdomain.com    A    YOUR_LINODE_IP
```

**Note:** You only need ONE A record for the relay server hostname, not one per domain you're sending from.

#### 4.2 SPF Record
```
domain1.com    TXT    "v=spf1 ip4:YOUR_LINODE_IP include:_spf.protonmail.ch ~all"
domain2.com    TXT    "v=spf1 ip4:YOUR_LINODE_IP include:_spf.protonmail.ch ~all"
```

#### 4.3 PTR Record (Reverse DNS)
Configure through Linode control panel (Settings → Network → IP Addresses → Edit RDNS):
```
YOUR_LINODE_IP  →  smtp-relay.yourdomain.com
```

**Important:** The reverse DNS must match your server's hostname for better email deliverability.

#### 4.4 DKIM Setup (Optional but Recommended)
```bash
# Install OpenDKIM
apt install -y opendkim opendkim-tools

# Generate keys for each domain
mkdir -p /etc/opendkim/keys/domain1.com
opendkim-genkey -D /etc/opendkim/keys/domain1.com/ -d domain1.com -s default

mkdir -p /etc/opendkim/keys/domain2.com
opendkim-genkey -D /etc/opendkim/keys/domain2.com/ -d domain2.com -s default

# Set permissions
chown -R opendkim:opendkim /etc/opendkim/keys
chmod 640 /etc/opendkim/keys/*/default.private
```

Add DKIM TXT records:
```
default._domainkey.domain1.com    TXT    "v=DKIM1; k=rsa; p=YOUR_PUBLIC_KEY"
default._domainkey.domain2.com    TXT    "v=DKIM1; k=rsa; p=YOUR_PUBLIC_KEY"
```

Configure OpenDKIM (`/etc/opendkim.conf`):
```conf
Syslog yes
UMask 002
Socket inet:8891@localhost
KeyTable /etc/opendkim/KeyTable
SigningTable /etc/opendkim/SigningTable
ExternalIgnoreList /etc/opendkim/TrustedHosts
InternalHosts /etc/opendkim/TrustedHosts
```

Create `/etc/opendkim/KeyTable`:
```
default._domainkey.domain1.com domain1.com:default:/etc/opendkim/keys/domain1.com/default.private
default._domainkey.domain2.com domain2.com:default:/etc/opendkim/keys/domain2.com/default.private
```

Create `/etc/opendkim/SigningTable`:
```
*@domain1.com default._domainkey.domain1.com
*@domain2.com default._domainkey.domain2.com
```

Create `/etc/opendkim/TrustedHosts`:
```
127.0.0.1
localhost
YOUR_LINODE_IP
```

Update Postfix to use OpenDKIM (`/etc/postfix/main.cf`):
```conf
milter_default_action = accept
milter_protocol = 6
smtpd_milters = inet:127.0.0.1:8891
non_smtpd_milters = $smtpd_milters
```

#### 4.5 DMARC Record (Optional but Recommended)
```
_dmarc.domain1.com    TXT    "v=DMARC1; p=none; rua=mailto:your-email@protonmail.com"
_dmarc.domain2.com    TXT    "v=DMARC1; p=none; rua=mailto:your-email@protonmail.com"
```

### Phase 6: Monitoring and Maintenance

#### 6.1 Log Monitoring
```bash
# View real-time logs
tail -f /var/log/postfix.log

# Check for errors
grep "error\|warning\|reject" /var/log/postfix.log | tail -20

# View mail queue
mailq
```

#### 6.2 Set Up Log Rotation
Create `/etc/logrotate.d/postfix`:
```conf
/var/log/postfix.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 0640 postfix adm
    postrotate
        systemctl reload postfix > /dev/null
    endscript
}
```

#### 6.3 Basic Monitoring Script
Create `/usr/local/bin/check-postfix.sh`:
```bash
#!/bin/bash
# Simple Postfix health check

# Check if Postfix is running
if ! systemctl is-active --quiet postfix; then
    echo "ALERT: Postfix is not running!"
    systemctl start postfix
fi

# Check queue size
QUEUE_SIZE=$(mailq | tail -1 | awk '{print $5}')
if [ "$QUEUE_SIZE" -gt 100 ]; then
    echo "WARNING: Mail queue has $QUEUE_SIZE messages"
fi

# Check for common errors
ERRORS=$(grep -c "error\|fatal" /var/log/postfix.log | tail -100)
if [ "$ERRORS" -gt 10 ]; then
    echo "WARNING: $ERRORS errors in recent logs"
fi
```

Add to crontab:
```bash
# Run every 5 minutes
*/5 * * * * /usr/local/bin/check-postfix.sh
```

#### 6.4 Rate Limiting (Optional)
To prevent abuse, add to `/etc/postfix/main.cf`:
```conf
# Limit rate per sender
smtpd_client_message_rate_limit = 100
smtpd_client_recipient_rate_limit = 200

# Anvil settings
anvil_rate_time_unit = 60s
```

## Microservice Configuration

Configure your microservices to use the following SMTP settings:

```
SMTP Host: smtp-relay.yourdomain.com (or YOUR_LINODE_IP)
SMTP Port: 587
SMTP Security: STARTTLS (optional, can use unencrypted)
Authentication: None (IP-based security)
From Address: noreply@domain1.com (or any valid address for your domain)
```

### Example: Node.js with Nodemailer
```javascript
const nodemailer = require('nodemailer');

const transporter = nodemailer.createTransport({
  host: 'smtp-relay.yourdomain.com',
  port: 587,
  secure: false,
  // No auth needed with IP-based security!
  tls: {
    rejectUnauthorized: true  // Set to false if using self-signed cert
  }
});

const mailOptions = {
  from: 'noreply@domain1.com',
  to: 'recipient@protonmail.com',
  subject: 'Test Email',
  text: 'This is a test email from microservice'
};

transporter.sendMail(mailOptions, (error, info) => {
  if (error) {
    console.log('Error:', error);
  } else {
    console.log('Email sent:', info.response);
  }
});
```

### Example: Python with smtplib
```python
import smtplib
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

smtp_server = 'smtp-relay.yourdomain.com'
smtp_port = 587

msg = MIMEMultipart()
msg['From'] = 'noreply@domain1.com'
msg['To'] = 'recipient@protonmail.com'
msg['Subject'] = 'Test Email'
msg.attach(MIMEText('This is a test email from microservice', 'plain'))

server = smtplib.SMTP(smtp_server, smtp_port)
server.starttls()  # Optional, for encrypted connection
# No login needed with IP-based security!
server.send_message(msg)
server.quit()
```

## Security Considerations

1. **IP Restrictions**: 
   - Firewall (ufw) only allows SMTP ports from trusted IPs
   - Postfix only accepts connections from IPs in `mynetworks`
   - Dual-layer IP-based security

2. **Firewall**: Only allow necessary ports (22, 587, optionally 25) from specific IPs

3. **Fail2ban**: Optional but recommended for SSH protection:
   ```bash
   apt install -y fail2ban
   ```
   
4. **Regular Updates**: Keep system and Postfix updated
   ```bash
   apt update && apt upgrade
   ```

5. **Monitor Logs**: Regularly check `/var/log/postfix.log` for suspicious activity
   ```bash
   # Check for unauthorized access attempts
   grep "reject" /var/log/postfix.log | tail -50
   ```

6. **Backup Configuration**: 
   ```bash
   tar -czf postfix-backup-$(date +%Y%m%d).tar.gz /etc/postfix /etc/opendkim
   ```

7. **Document Your IPs**: Keep a list of authorized microservice IPs for reference
   ```bash
   # Create IP inventory
   cat > /etc/postfix/authorized_ips.txt <<EOF
   # Authorized Microservice IPs
   MICROSERVICE_IP_1  # Service: website-api-prod
   MICROSERVICE_IP_2  # Service: webhook-handler
   EOF
   ```

## Troubleshooting

### Common Issues

#### 1. "Relay access denied"
- Check `smtpd_relay_restrictions` includes `permit_sasl_authenticated`
- Verify authentication credentials are correct
- Check that domain is in `relay_domains`

#### 2. Authentication fails
```bash
# Check SASL is working
postconf -a

# Test authentication
testsaslauthd -u username -p password -s smtp

# Check logs
grep sasl /var/log/postfix.log
```

#### 3. Emails marked as spam
- Verify SPF, DKIM, DMARC records
- Check reverse DNS is set correctly
- Test at mail-tester.com
- Ensure sender domain matches authentication domain

#### 4. TLS/SSL errors
```bash
# Test TLS
openssl s_client -connect localhost:587 -starttls smtp

# Check certificate
postconf smtpd_tls_cert_file smtpd_tls_key_file
```

#### 5. Queue buildup
```bash
# View queue
mailq

# Flush queue
postfix flush

# Delete all queued mail (if needed)
postsuper -d ALL
```

## IP-Based Security Configuration

This guide uses **IP-based only security** - your microservices connect using their static IP addresses without needing usernames or passwords.

**How it works**:
- Firewall only allows connections from your specific microservice IPs
- Postfix only allows relay from those same trusted IPs
- Two layers of protection without password management

**Advantages**:
- Simpler configuration
- No passwords to manage or rotate
- Faster (no authentication overhead)
- Still very secure with dual-layer IP restrictions

**Already configured** in Phase 1 (firewall) and Phase 2 (Postfix)!

### Managing Trusted IPs

#### Adding a New Microservice IP
1. Add to firewall:
   ```bash
   ufw allow from NEW_MICROSERVICE_IP to any port 587 proto tcp
   ```

2. Add to Postfix `/etc/postfix/main.cf`:
   ```conf
   mynetworks = 127.0.0.0/8, IP_1, IP_2, NEW_IP
   ```

3. Reload Postfix:
   ```bash
   postfix reload
   ```

#### Removing a Microservice IP
1. Remove from firewall:
   ```bash
   ufw delete allow from OLD_MICROSERVICE_IP to any port 587 proto tcp
   ```

2. Remove from Postfix `main.cf`

3. Reload Postfix:
   ```bash
   postfix reload
   ```

### IP Ranges (Optional)
If your microservices are on a subnet, you can allow entire ranges:

```conf
# Allow entire subnet
mynetworks = 127.0.0.0/8, 192.168.1.0/24

# Or specific ranges
mynetworks = 127.0.0.0/8, 10.0.1.0/24, 10.0.2.0/24
```

Firewall equivalent:
```bash
ufw allow from 192.168.1.0/24 to any port 587 proto tcp
```

### Testing IP Restrictions

```bash
# From a trusted IP (should succeed)
telnet mail.yourdomain.com 587

# From an untrusted IP (should be rejected at firewall level - connection refused)
# Or if it reaches Postfix, you'll see "Relay access denied"
```

### Monitoring Rejected Connections

```bash
# View rejected connection attempts
grep "reject" /var/log/postfix.log | tail -20

# View connections from specific IP
grep "MICROSERVICE_IP_1" /var/log/postfix.log | tail -20
```

## Adding New Domains

To add a new domain:

1. Update `/etc/postfix/main.cf`:
   ```conf
   relay_domains = domain1.com, domain2.com, domain3.com
   ```

2. Configure DNS records (SPF, DKIM, DMARC) for the new domain

3. Generate DKIM keys:
   ```bash
   mkdir -p /etc/opendkim/keys/domain3.com
   opendkim-genkey -D /etc/opendkim/keys/domain3.com/ -d domain3.com -s default
   chown -R opendkim:opendkim /etc/opendkim/keys/domain3.com
   chmod 640 /etc/opendkim/keys/domain3.com/default.private
   ```

4. Update OpenDKIM configuration files (`KeyTable`, `SigningTable`)

5. Restart services:
   ```bash
   systemctl restart postfix opendkim
   ```
